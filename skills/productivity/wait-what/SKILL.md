# Wait, What?

That last message didn't land. Re-pitch it.

Give the context that was missing. Use short sentences and simple, direct words. Use the project's own vocabulary from `CONTEXT.md` (follow `CONTEXT-MAP.md` to the right one if the repo has several), because those are words the user already agreed to.

Rules for the re-pitch:

- **Lead with the point**, then explain it. Don't rebuild the reasoning first.
- **Say what it means for them** — what changes, what it costs, what they'd decide differently.
- **No jargon, and no jargon in disguise.** If a technical term is genuinely load-bearing, name it once and define it in the same breath.
- **Don't just repeat it louder.** If the first framing didn't work, the second needs a different angle: an analogy, a concrete example, or the consequence rather than the mechanism.
- **Don't apologise or pad.** Re-pitch and move on.

Then check it landed: ask whether that version made sense, or whether a different angle would help.

This skill is invoked **only** by the user typing it. Never fire it on your own — deciding someone looks confused and re-explaining unprompted is obnoxious.
